# DOC-031 — Runtime Execution Overview

Version: 1.0

Status: Final

---

# 1. Objective

Define the complete runtime execution architecture for AI DevOS.

This document specifies how a workflow stage is executed from the moment the Workflow Engine dispatches a stage until the stage completes successfully or fails.

This document is the architectural contract for all runtime execution documents.

No implementation details belong in this document.

---

# 2. Scope

This document defines:

- Runtime execution lifecycle
- Stage execution lifecycle
- Agent execution lifecycle
- LLM execution flow
- Artifact generation flow
- Review flow
- Memory update flow
- Workflow transition flow

This document does not define:

- Individual classes
- Method implementations
- Prompt formats
- LLM providers
- Agent implementations

Those are documented separately.

---

# 3. Runtime Overview

The runtime executes one workflow stage at a time.

Only one engineering stage is active.

Only one session is active.

Only one agent executes.

Only one reviewer validates.

Only approved artifacts update project memory.

# 5. Runtime Responsibilities

Workflow Engine

Responsible for:

- Starting execution
- Selecting next stage
- Verifying dependencies
- Waiting for review result
- Transitioning workflow

Execution Engine

Responsible for:

- Executing exactly one stage
- Building execution context
- Invoking the correct agent
- Returning the generated artifact

Context Builder

Responsible for:

- Building AgentContext
- Loading runtime memory
- Loading project memory
- Loading approved artifacts
- Loading review history

Agent

Responsible for:

- Solving one engineering task
- Building prompts
- Calling the LLM
- Returning one artifact

LLM Manager

Responsible for:

- Selecting provider
- Sending request
- Returning response

Artifact Manager

Responsible for:

- Creating draft artifact
- Storing artifact
- Updating artifact state

Reviewer

Responsible for:

- Validating artifact
- Returning Approved or Rejected

Memory Manager

Responsible for:

- Updating project memory
- Updating artifact memory
- Never updating draft memory

# 10. Runtime Dependencies

Execution Engine depends on:

- Context
- Agent
- Artifact

Agent depends on:

- Prompt Builder
- LLM Manager

LLM Manager depends on:

- Provider

Reviewer depends on:

- Artifact

Workflow Engine depends on:

- Execution Engine
- Reviewer

Memory Manager depends on:

- Approved Artifact

---

# 11. Runtime Rules

Exactly one workflow executes.

Exactly one stage executes.

Exactly one session exists.

Exactly one agent executes.

Exactly one artifact is generated.

Exactly one reviewer validates.

Draft artifacts never update memory.

Rejected artifacts never advance workflow.

Only approved artifacts become project knowledge.

---

# 12. Runtime Validation

A runtime execution is valid only if:

✓ Dependencies verified

✓ Session created

✓ Context built

✓ Agent executed

✓ LLM completed

✓ Artifact generated

✓ Reviewer executed

✓ Memory updated

✓ Workflow advanced
