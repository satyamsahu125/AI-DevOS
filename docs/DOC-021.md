# DOC-021 — Shared DTOs

Version: 1.0

Status: Draft

Phase: Product Owner MVP

Package: Shared / DTOs

---

# 1. Objective

Implement every Data Transfer Object (DTO) shared across the application.

DTOs are used only for communication between packages.

DTOs never contain business logic.

DTOs never represent persistent entities.

---

# 2. Scope

The DTO package is responsible for

• Project Requests

• Project Responses

• Workflow Requests

• Workflow Responses

• Execution Requests

• Execution Results

• LLM Requests

• LLM Responses

• Review Requests

• Review Results

DTOs are NOT responsible for

• Validation

• Persistence

• Business Rules

• State Management

---

# 11. Package State Machine

Not Applicable

---

# 12. Implementation Rules

1. Every DTO uses @dataclass(slots=True).

2. DTOs contain only data.

3. No methods.

4. No validation.

5. No business logic.

6. No persistence.

7. DTOs are immutable after creation.

---

# 13. Validation Checklist

✓ All DTOs implemented

✓ Dataclasses only

✓ No business logic

✓ No application imports

✓ Package compiles independently

---

# 14. Exit Criteria

The DTO package is complete when

• Every package communicates using DTOs.

• No package exposes internal models directly across API boundaries where DTOs are required.

• DTOs remain lightweight immutable transport objects.
