DOC-029 — Repository Migration & Source of Truth

Version: 1.0

Status: Mandatory

---

# 1. Objective

Define the single source of truth for the repository.

The project formerly contained two independent implementations, but those implementations have now been consolidated into the backend application tree.

Current state

backend/
    app/
        ...

Only one production implementation remains.

---

# 2. Problem

Current State

Repository

├── backend/
│   └── app/

The former aidevos tree has been removed.

---

# 3. Risks

Duplicate classes

Duplicate managers

Different DTOs

Different models

Different APIs

Different workflows

Different dependency graphs

Different folder structures

Conflicting imports

Undocumented behavior

Two implementations eventually diverge.

---

# 4. Repository Rule

There must be exactly one implementation.

Exactly one package owns every module.

No duplicated package is allowed.

No duplicated manager is allowed.

No duplicated model is allowed.

No duplicated DTO is allowed.

No duplicated workflow is allowed.

---

# 5. Source of Truth

Source of Truth

backend/

Everything inside backend becomes the production implementation.

The former aidevos tree has been removed and no longer exists in the repository.

# 7. Merge Rules

If a file existed only in the former aidevos tree

↓

Move it into backend/app if needed during migration.

If a file exists only inside backend

↓

Keep backend version.

If both exist

↓

Compare implementation.

↓

Choose newer version.

↓

Merge manually.

Delete duplicate.

Repository contains exactly one implementation.

Only backend/app contains production code.
