# DOC-005 — Dependency Matrix

Version: 1.0

Status: Draft

Phase: Product Owner MVP

---

# 1. Purpose

This document defines every dependency allowed inside AI DevOS.

Its objectives are:

- prevent circular dependencies
- define ownership boundaries
- define import direction
- define module visibility
- define runtime communication
- define implementation constraints

No source file may violate this document.

---

# 2. Dependency Philosophy

The system follows a layered architecture.

Dependencies always point downward.

No dependency may point upward.

No dependency may point sideways unless explicitly allowed.

---

# 7. Public API Matrix

Every package exposes only its public API.

Example

Workflow exposes

```text
WorkflowEngine

WorkflowState
```

Internal implementation remains private.

Execution exposes

```text
ExecutionEngine
```

Nothing else.

---

# 8. Internal Visibility

Internal classes may never be imported outside their package.

Example

```text
memory/providers/internal_provider.py
```

may only be imported inside

```text
memory/
```

---

# 9. Circular Dependency Rules

The following are prohibited.

```text
Workflow ↔ Execution

Workflow ↔ Memory

Execution ↔ Context

Context ↔ Agents

Artifacts ↔ Memory

Review ↔ Workflow

Review ↔ Execution
```

Every dependency graph must remain acyclic.

---

# 10. File-Level Dependency Rule

Every source file shall depend on:

- files within the same package
- public interfaces of lower packages
- shared DTOs

No file may import private implementation classes from another package.

---


# Dependency Validation Rules

Before implementing a package, verify:

1. All required dependency packages are complete.
2. Every required public interface exists.
3. No forbidden package is imported.
4. No circular dependency is introduced.
5. Every dependency follows the package dependency graph.

If any rule fails, implementation shall stop.
---

# 12. Implementation Rules

Before creating any class, verify:

1. Its package owns the responsibility.
2. Its dependencies are allowed.
3. Required public interfaces already exist.
4. No forbidden import is introduced.

If any rule fails, implementation must stop.

---

# 13. Exit Criteria

This document is complete when:

- Every package has allowed dependencies.
- Every package has forbidden dependencies.
- Runtime ownership is defined.
- Public API boundaries are defined.
- Circular dependency rules are documented.
- File-level dependency rules are documented.
