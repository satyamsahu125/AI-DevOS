# AI DevOS System Working & Architecture

This document details the working mechanism, architecture, 12-stage pipeline, memory system, and execution workflow of **AI DevOS**.

---

## 1. Overview

**AI DevOS** is an automated multi-agent software engineering system designed to take a plain-text prompt describing an application and transform it into a complete, runnable codebase with real files on disk.

Unlike single-prompt code generators, AI DevOS breaks down the software development lifecycle into **12 specialized stages**. Each stage is governed by a dedicated AI agent, structured Pydantic schema outputs, an automated three-tier review system, and persistent stage memory.

---

## 2. High-Level Architecture

The system consists of two primary modules communicating over an API:

```
[ Frontend: Vite + React 19 + TS ] <--- HTTP API (/api/*) ---> [ Backend: FastAPI + Python 3.12 ]
                                                                      |
                                                                      +---> Workflow Engine
                                                                      +---> 12-Stage Agents
                                                                      +---> Memory & Artifact Managers
                                                                      +---> LLM Providers (Ollama / AWS Bedrock)
```

1. **Frontend (Dashboard & Workspace UI)**
   - Technology: Vite, React 19, TypeScript, Tailwind CSS.
   - Purpose: Provides a live build log viewer, project rail, stage status visualizer, file tree explorer, and LLM configuration settings.

2. **Backend (API & Orchestration Core)**
   - Technology: Python 3.12, FastAPI.
   - Design Choice: Synchronous execution pipeline for deterministic stage ordering and predictable resource usage.
   - Responsibilities: Workspace folder management, project memory, LLM provider routing, artifact storage, and pipeline execution.

3. **LLM Provider Layer**
   - **Ollama**: Local model execution (default model: `qwen2.5-coder:7b`).
   - **AWS Bedrock**: Cloud model execution via Bedrock Runtime Converse API.
   - Runtime switchable via `GET/POST /settings/llm`.

---

## 3. The 12-Stage Pipeline

Execution moves strictly in sequence through 12 stages. Each stage consumes context generated by prior stages:

| # | Stage Key | Responsible Agent | Output / Role |
|---|---|---|---|
| 1 | `strategic_review` | StrategicReviewAgent | Project viability assessment and initial strategy |
| 2 | `product_owner` | ProductOwnerAgent | Requirements specification, user stories, acceptance criteria |
| 3 | `architect` | ArchitectAgent | Tech stack definition, system modules, data models, API spec |
| 4 | `designer` | DesignerAgent | Page layouts, component specs, UI/UX design rules |
| 5 | `security` | SecurityAgent | Vulnerability assessment and security guidelines |
| 6 | `file_planner` | FileStructurePlannerAgent | Concrete file tree plan (`{path, module, purpose}`) |
| 7 | `backend` | BackendDeveloperAgent | Real backend source files (writes files to disk) |
| 8 | `frontend` | FrontendDeveloperAgent | Real frontend source files (writes files to disk) |
| 9 | `qa` | QAAgent | Test plan, test cases, and quality evaluation |
| 10 | `document` | DocumentAgent | README, installation guides, and API documentation |
| 11 | `devops` | DevOpsAgent | Dockerfile, CI/CD, and deployment instructions |
| 12 | `retro` | RetroAgent | Pipeline retrospective and quality summary |

*Note: Only Stage 7 (`backend`) and Stage 8 (`frontend`) directly write code files to `temp-workspace/{project_id}/project/`. Other stages generate structured review documents.*

---

## 4. The Execute -> Review -> Retry Loop

For every stage in the pipeline, AI DevOS executes the following loop:

```
[Agent Prompt Construction]
            |
            v
   [LLM Generation Call]
            |
            v
[Pydantic Schema Validation]
            |
            v
  [Automated Reviewer Check]
     /                  \
 (Passed)             (Failed)
   /                      \
  v                        v
[Approve & Save]    [Inject Reviewer Feedback & Retry]
```

1. **Prompt Construction**: Gathers short-term memory, project requirements, and previous approved stage artifacts.
2. **Generation**: LLM produces structured output conforming to the stage schema.
3. **Validation & Review**: Automated reviewer checks output against schema and domain rules.
4. **Retry Loop**: If review fails, the reviewer's feedback is appended to the prompt for a targeted retry.

---

## 5. Memory System

AI DevOS maintains three distinct memory layers:

- **Short-Term Memory**: Holds immediate task context and current stage parameters.
- **Working Memory**: Accumulates approved outputs from preceding stages to pass downstream.
- **Long-Term Memory**: Persists project metadata, execution logs, review history, and generated artifacts in `temp-workspace/`.

## 6. How to Run & Verify

### Start Backend
```powershell
cd F:\AI-DevOS3\backend
python -m uvicorn app.main:app --reload
```

### Start Frontend
```powershell
cd F:\AI-DevOS3\frontend
npm run dev
```

### Run Verification Tests
```powershell
# Backend tests
cd F:\AI-DevOS3\backend
python -m pytest tests/ -q

# Frontend typecheck & build
cd F:\AI-DevOS3\frontend
npx tsc -b --noEmit
npm run build
```
