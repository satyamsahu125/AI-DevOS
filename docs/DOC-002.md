# DOC-002 — High-Level Blueprint

Version: 1.0

Status: Draft

Phase: Product Owner MVP

---

# 1. Purpose

This document defines the high-level architecture of AI DevOS for Phase 1.

It establishes:

- system boundaries
- module ownership
- execution boundaries
- communication direction
- responsibility distribution

This document does not define class implementations.

---

# 2. System Architecture

The architecture consists of independent modules.

Each module owns a single responsibility.

Modules communicate only through public interfaces.

No module may directly manipulate another module's internal state.

# 4. Module Responsibilities

## Project

Owns

- project creation
- project metadata
- project lifecycle

Never

- execute agents
- store memory

---

## Workspace

Owns

- workspace metadata
- workspace location
- workspace registration

Never

- edit source code
- execute workflow

---

## Workflow

Owns

- stage order
- dependency validation
- workflow lifecycle

Never

- call LLM
- edit files
- manage memory

---

## Execution

Owns

- agent execution
- execution lifecycle
- execution context

Never

- store memory
- validate reviews

---

## Context

Owns

- AgentContext construction
- context selection
- context budgeting

Never

- execute agents
- modify memory

---

## Agent

Owns

- prompt generation
- reasoning
- artifact generation

Never

- call memory directly
- edit workflow

---

## LLM

Owns

- provider communication
- model invocation
- request formatting
- response parsing

Never

- modify workflow
- update memory

---

## Review

Owns

- artifact validation
- approval
- rejection
- reviewer feedback

Never

- generate artifacts
- execute workflow

---

## Artifact

Owns

- artifact storage
- artifact versioning
- approved artifact retrieval

Never

- update project memory

---

## Memory

Owns

- runtime memory
- project memory
- artifact extraction

Never

- execute workflow
- generate artifacts

---

## Session

Owns

- stage session
- retry counter
- session lifecycle

Never

- execute agents

---

## Shared

Owns

- DTOs
- enums
- constants
- shared utilities

Never

- business logic

---

# 5. Module Communication Rules

Allowed communication

```text
Project
    ↓
Workspace
    ↓
Workflow
    ↓
Execution
    ↓
Context
    ↓
Agent
    ↓
LLM
    ↓

    ↓

    ↓
```

# 7. Dependency Direction

Dependencies always point downward.

```text
Project
    ↓
Workflow
    ↓
Execution
    ↓
Context
    ↓
Agent
    ↓
LLM
```

Memory is never above Workflow.

Reviewer is never above Execution.

---

# 8. Data Ownership

Every data object has exactly one owner.

| Data | Owner |
|------|-------|
| Project | Project Module |
| Workspace | Workspace Module |
| Workflow State | Workflow Module |
| Execution Context | Context Module |
| Prompt | Agent Module |
| LLM Response | LLM Module |
| Review Result | Review Module |
| Artifact | Artifact Module |
| Memory | Memory Module |
| Session | Session Module |

Ownership cannot be shared.

# 10. Forbidden Dependencies

The following dependencies are prohibited.

Workflow → Memory

Workflow → LLM

Agent → Memory

Agent → Workflow

Review → Workflow

Review → Context

Artifact → Workflow

Memory → Workflow

Memory → Execution

Workspace → Memory

Project → Execution

---

# 11. Architectural Principles

1. One responsibility per module.

2. One owner per resource.

3. No circular dependencies.

4. No shared mutable state.

5. Memory updates only after approval.

6. Workflow never calls LLM directly.

7. Agents consume only AgentContext.

8. Modules communicate only through public APIs.

9. Internal implementation is private.

10. Business logic remains outside infrastructure modules.
