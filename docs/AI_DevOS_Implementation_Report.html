🏗️ System Architecture Overview

AI DevOS is a 19-stage autonomous software engineering platform. A single project request flows through a deterministic pipeline managed by the Workflow Engine — the sole orchestrator. Agents are stateless; they communicate only through typed artifacts stored by the Execution Engine.

⚖️ Overall System Merits & Demerits

✅ System Merits

Stateless agents — all state lives in artifacts and memory; agents are independently replaceable
Single orchestrator — WorkflowEngine is the only controller; no agent-to-agent calls prevent race conditions
Typed DTOs throughout — StageContext, RetryPlan, SandboxResult, ModelProfile all typed; no hidden string contracts
Non-fatal error contract — every cross-cutting concern (memory, sandbox, intelligence) is wrapped; one failure never kills the pipeline
Provider-agnostic — switch Bedrock → Gemini → Ollama via .env only; zero code changes
Deterministic code generation — ModelRouter sets temp=0.05 for BackendDeveloper/FrontendDeveloper
Human-in-the-loop — 3 structured gates without breaking automation flow
Docker-deployable — full stack in one docker-compose up with Redis, API, and worker

⚠️ System Demerits & Future Work

No JWT/RBAC — API key auth is sufficient for MVP but lacks per-user permissions and token expiry
Thread-based gates not HA-ready — gate state lives in memory; horizontal scaling requires Redis-backed pause state
FileRegistry not persisted — lost on restart; needs SQLite backing for long-running projects
TemplateEngine not yet injected — built and tested but not yet wired into stage prompt assembly
Rejection classification by keywords — IntelligentRetryEngine uses text matching, not LLM classification
Sandbox needs Docker in production — subprocess fallback has no isolation; unsafe for untrusted code
No rate limiting — API has no per-IP or per-key request throttling
Legacy _with_* methods — Phase 0 kept the old enrichment fallback; needs a cleanup pass to remove dead code
