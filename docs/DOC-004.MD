# DOC-004 — Folder Structure

Version: 1.0

Status: Draft

Phase: Product Owner MVP

---

# 1. Purpose

This document defines the official repository structure for Phase 1.

It specifies:

- package hierarchy
- ownership
- allowed files
- forbidden files
- package responsibilities

No source code shall be created outside this structure.

---

# 2. Root Structure

```text
backend/

├── app/
│
├── config/
│
├── docs/
│
├── tests/
│
├── requirements.txt
│
└── main.py
```

Only these top-level directories are permitted. The legacy aidevos directory has been removed and is no longer part of the production repository.

---

app/

# 5. Allowed Files

Every package may only contain files belonging to its responsibility.

Example

memory/

```text
manager.py

provider.py

runtime_store.py

types.py
```

Execution

```text
engine.py

executor.py

result.py
```

Context

```text
context.py

builder.py

budget.py

selectors/
```

No unrelated files shall exist.

---

# 6. Forbidden Files

The following generic files are prohibited unless explicitly specified.

```text
helper.py

helpers.py

utils.py

common.py

misc.py

temp.py

new.py

old.py

manager2.py

service.py

service_v2.py
```

Every file shall have a single well-defined responsibility.

---

# 7. Package Rules

Every package shall:

- expose one responsibility
- hide internal implementation
- communicate only through public interfaces

Packages shall never directly modify another package's internal state.

---

# 8. Import Rules

Imports shall always follow this direction.

```text
Project

↓

Workflow

↓

Execution

↓

Context

↓

Agents

↓

LLM

↓

Review

↓

Artifacts

↓

Memory
```

Reverse imports are prohibited.

Circular imports are prohibited.

---

# 9. Ownership Rules

Every file belongs to exactly one package.

Moving a file between packages requires updating the architecture documentation.

---

# 10. Package Expansion Rules

New files may only be added when:

- a new architecture document exists
- the file responsibility is defined
- ownership is documented

Packages shall never grow organically.

---

# 11. Validation Checklist

Folder structure is complete when:

✓ All packages exist.

✓ Every package has a documented owner.

✓ Allowed files are defined.

✓ Forbidden files are defined.

✓ Import direction is documented.

✓ Ownership rules are documented.

| 3 | Memory | Shared, Artifact |

| 7 | Session | Shared, Context |
| 8 | LLM | Shared |
| 9 | Agents | Shared, Context, LLM, Artifact |
|10 | Execution | Shared, Agents, Session, Context |
|11 | Workflow | Shared, Execution, Session |
|12 | Project | Shared, Workflow, Workspace |

This order is mandatory.
