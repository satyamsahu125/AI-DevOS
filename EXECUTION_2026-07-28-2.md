## Task 20 — Extract SlimContextExtractor mixin from 5 duplicate prompt builders

### Previous
Each of the five downstream prompt builders (`architect_builder.py`, `designer_builder.py`,
`backend_builder.py`, `frontend_builder.py`, `document_builder.py`) had its own private
`_parse_json()` and `_extract_*_context()` helpers.  The implementations diverged in subtle
ways: different fallback truncation lengths (2000 vs 3000 chars), different handling of
`api_endpoints` sub-fields, and inconsistent `_LIST_CAPS` for long lists.  Every builder
was duplicating the same JSON-parse / key-filter / field-trim logic.

### Changed
- Created `backend/app/prompt/context_extractor.py` — a `SlimContextExtractor` mixin class.
- Public API: `parse_artifact_json(raw)`, `_unwrap_structured(data)`, `extract(raw, keys)`,
  `_trim_fields(data, keys)`, `get_raw_content(context)`.
- Centralized `_LIST_CAPS` dict limits list fields (`api_endpoints→30`, `modules→20`, etc.).
- `api_endpoints` trimmed to `name/method/path` only; `requirements` to `name/description` only.
- Returns `""` on parse failure; callers fall back to `raw_content[:2000–3000]`.
- All five builders refactored to inherit `PromptBuilder, SlimContextExtractor` and replaced
  their private helpers with `self.get_raw_content(context)` + `self.extract(raw, _KEYS)`.
- Per-stage key whitesets (`_ARCH_KEYS`, `_DESIGN_ARCH_KEYS`, `_BACKEND_KEYS`,
  `_FRONTEND_KEYS`, `_DOC_KEYS`) kept in each builder file for locality.

### Next
- Integration test that feeds a 30 KB fake artifact chain through each builder and asserts
  the resulting prompt is under a token budget (e.g. 8 K tokens).
- `_LIST_CAPS` values are heuristic; revisit when we have real production data on which
  stages produce the longest lists.

## Task 21 — Fix Review Design button not resetting designDismissedRef

### Previous
`WorkspacePage.tsx` had a "Review Design" button that called `setDesignOpen(true)`.  However
`designDismissedRef.current` was not cleared on that explicit click, so if the user had
previously dismissed the auto-opened modal, the WS heartbeat path (guarded by the ref)
prevented the button from re-opening it via the heartbeat — but the explicit button click
worked.  The real bug was that `onClose` set `designDismissedRef.current = true` and then
the WS state-change `useEffect` (correctly guarded) never re-opened the modal.  A secondary
bug: the explicit "Review Design" button click did NOT reset the ref, meaning a subsequent
WS heartbeat could still be blocked when the user closed the explicit-button-triggered modal.

### Changed
- Added `designDismissedRef = useRef(false)` to track explicit dismissal.
- `useEffect` for `pipeline.state`: calls `setDesignOpen(true)` only when
  `!designDismissedRef.current`; resets ref to `false` when pipeline advances past
  `design_review` state.
- `onClose` callback: sets `designDismissedRef.current = true`.
- `onActionCompleted` callback: resets `designDismissedRef.current = false`.
- "Review Design" explicit button: sets `designDismissedRef.current = false` **before**
  calling `setDesignOpen(true)`, ensuring the next WS heartbeat still works correctly.

### Next
- Playwright test: dismiss modal → click "Review Design" button → assert modal reopens →
  dismiss again → simulate WS heartbeat with same `design_review` state → assert modal stays
  closed (ref guard working).
- Consider whether `designDismissedRef` should be reset on project change/reload.

## Task 22 — Upgrade Reviewer empty-required-keys to ASK_HUMAN for critical stages

### Previous
`reviewer.py` treated all empty-required-field findings as `FLAG` (advisory).  A stub output
from `WriteArchitecture` (e.g. one-sentence `description`, empty `components` list) would
score low but still pass review automatically — the pipeline continued with incomplete
architecture into backend code generation.  This caused cascading failures where downstream
agents had nothing meaningful to work with.

### Changed
- Added `import re` and 6 `_BOILERPLATE_PATTERNS` regexes (detects "placeholder", "TODO",
  "coming soon", "sample output", etc.).
- Added `_MIN_WORDS_TEXT_STAGE = 30` sentinel for text-only stage minimum.
- Added `_REQUIRED_STRUCTURED_KEYS` dict mapping schema names → required field lists.
- Added `_CRITICAL_SCHEMAS = frozenset({"WriteArchitecture", "WriteRequirements",
  "WriteDesign", "WriteBackendFiles", "WriteFrontendFiles"})`.
- Empty required fields in critical schemas escalate to `ReviewTier.ASK_HUMAN` (blocks
  pipeline approval); non-critical schemas keep `ReviewTier.FLAG` (advisory only).
- Updated `_check_flag()` to accept and populate `human_questions: list[str] | None`.
- Updated `_compute_quality_score()` to penalize empty required fields and boilerplate
  pattern matches.

### Next
- Unit tests for each `_BOILERPLATE_PATTERNS` regex and for the critical vs non-critical
  escalation path.
- Tune `_MIN_WORDS_TEXT_STAGE` threshold and boilerplate patterns against real agent output
  once the pipeline is exercised end-to-end.
- Consider adding a maximum-retry guard: if ASK_HUMAN fires 3 times for the same stage the
  pipeline should surface an error rather than looping indefinitely.

## Task 23 — Add cost prefix-match + /api/cost detail endpoint

### Previous
`CostTracker._estimate_cost()` used a direct dict lookup on `TOKEN_COST_PER_1K`.  A
versioned model name like `gemini-2.0-flash-001` (suffix appended by Google's API) had no
exact key and returned zero cost.  The `/projects/{project_id}/cost` endpoint only returned
a raw aggregate (`calls`, `prompt_tokens`, etc.) with no estimated USD cost and no per-stage
breakdown.

### Changed
**`cost_tracker.py`**
- Added `PRICING_LAST_UPDATED = "2026-07-28"` constant (imported by `logs.py`).
- Added 10 new pricing entries for Claude Haiku/Sonnet/Opus 4-5 variants and Gemini
  2.0-flash, 2.0-flash-lite, 1.5-flash, 1.5-pro.
- Added `_lookup_prices(model)` static method: exact lookup first; prefix-match fallback
  requiring a `"-"` segment boundary (`tail == "" or tail.startswith("-")`), selecting the
  longest matching key.
- Updated `_estimate_cost()` to use `_lookup_prices()`.

**`api/logs.py`**
- Imported `PRICING_LAST_UPDATED` from `cost_tracker`.
- Enriched `/projects/{project_id}/cost` response to include both backward-compatible
  aggregate fields and a full `stages[]` array with per-stage token/latency/success_rate,
  plus `estimated_cost_usd`, `most_expensive_stage`, `slowest_stage`,
  `total_latency_seconds`, `pricing_last_updated`.

### Next
- Unit tests for `_lookup_prices`: exact match, prefix match with version suffix, no-match
  fallback to `{}`.
- Update `TOKEN_COST_PER_1K` when Anthropic / Google publish new pricing.  The
  `PRICING_LAST_UPDATED` date is the freshness signal.
- Frontend Metrics tab should consume `stages[]` from the enriched endpoint instead of
  making a separate metrics call.
