## Task 26 — Fix SafetyPolicy._is_approved_artifact() DDL side-effect and path mismatch

### Previous
`SafetyPolicy._is_approved_artifact()` had two bugs:

**Bug 1 — DDL in a read method.**  
`_is_approved_artifact()` began with `CREATE TABLE IF NOT EXISTS artifacts (...)` every time
it was called.  DDL belongs in `_ensure_schema()` (called once at `__init__`), not inside a
query method.  This created a subtle coupling: if ArtifactManager ever changed its schema
and the `CREATE TABLE IF NOT EXISTS` in `_is_approved_artifact()` ran first, the tables could
diverge.  It also meant every overwrite check issued a DDL statement — unnecessary overhead.

**Bug 2 — Path comparison never matched.**  
`check()` resolves `target` to an absolute path before calling
`_is_approved_artifact(str(resolved_target))`.  But `ArtifactManager.save_artifact()` stores
`str(md_path)` which is a *relative* path (e.g. `temp-workspace/proj/artifacts/architect.md`)
when `WORKSPACE_ROOT` is not an absolute env-var value.  The `WHERE file_path = ?` query
compared an absolute path against stored relative paths — they never matched.  Result:
`_is_approved_artifact()` always returned `False`, so previously-approved artifacts were
never protected by the WARN gate on re-run.

**Bug 3 — Misleading retry reason string.**  
`attempt > 1` produced the reason `"writing retry attempt N alongside previous attempts is
expected"`.  In reality, the canonical artifact file (`.md`, `.json`) IS overwritten by each
retry — the snapshot (`.attempt-N.json`) is what's written alongside.  The "alongside"
wording implied no overwrite occurred, which was wrong.

### Changed
**`backend/app/execution/safety_policy.py`**

- `_ensure_schema()`: replaced single `CREATE TABLE IF NOT EXISTS safety_checks` with
  `executescript()` creating BOTH `safety_checks` AND `artifacts` tables.  Comment explains
  SafetyPolicy reads the artifacts table read-only; ArtifactManager owns all writes.

- `check()`: changed `self._is_approved_artifact(str(resolved_target))` →
  `self._is_approved_artifact(target)` — passes the original (un-resolved) path string,
  matching what ArtifactManager stores.  Updated retry reason string to:
  `"retry attempt N: overwriting canonical artifact and writing attempt-N snapshot"`.

- `_is_approved_artifact()`: removed `CREATE TABLE IF NOT EXISTS artifacts` DDL entirely.
  Updated docstring to document why target must be the un-resolved path.

### Next
- If `WORKSPACE_ROOT` is set to an absolute path in production, both sides will be absolute
  and match correctly even without this fix.  Now they also match when `WORKSPACE_ROOT` is
  relative (the default).  Add an integration test that confirms `_is_approved_artifact()`
  returns `True` for a path that ArtifactManager just wrote and marked approved.
- Consider resolving `workspace_root` in `ArtifactManager` at construction time so paths are
  always absolute everywhere — that would be the more robust long-term fix.

## Task 27 — Fix dependency_detector.py TODO in generated output

### Previous
`build_requirements_txt()` in `dependency_detector.py` appended
`f"{pkg}  # TODO: pin version"` to the generated `requirements.txt` for any package not
found in `PYTHON_VERSION_MAP`.  This embedded a developer-facing `TODO` comment in a user-
facing generated file.  The `logger.warning` already captured the actionable message for
developers; the TODO in the output was redundant and confusing (users see `requirements.txt`
and wonder whether they need to do something).

### Changed
**`backend/app/workspace/dependency_detector.py` line 212**

- Changed generated comment from `# TODO: pin version` →
  `# unpinned — add to PYTHON_VERSION_MAP`.
- Added a prose comment above the line explaining the intent (emit unpinned rather than
  block generation; warning captures the dev action needed).
- Updated `logger.warning` message to include the file name
  (`dependency_detector.py`) so developers know exactly where to add the mapping.

### Next
- Expand `PYTHON_VERSION_MAP` with the most common packages that agents are likely to
  request (FastAPI, uvicorn, SQLAlchemy, pydantic, httpx, pytest, alembic, celery, redis,
  etc.) to reduce the rate of unpinned entries in generated output.
- Add a CI check (or test) that asserts `build_requirements_txt(["fastapi", "pydantic"])`
  produces no `# unpinned` lines — fails fast when a common package is missing from the map.
